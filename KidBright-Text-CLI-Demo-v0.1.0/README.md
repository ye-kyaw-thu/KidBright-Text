# KidBright Text — Command-Line XML Demo Tools v0.1.0

These helper scripts batch-convert the installed Stage 5 `.kbt` examples into Blockly XML using the **actual Stage 5 compiler** (`app\kbt\compiler\kbtc.py`). They do not introduce new compiler commands or replace the KidBright IDE.

## Install

1. Extract the ZIP into your existing KBIDE root folder, for example:

   `<KBIDE_ROOT>`

   The ZIP creates a `KidBright-Text-CLI-Demo-v0.1.0` subfolder. The scripts auto-detect KBIDE one level above that folder. You do not need to overwrite any existing KBIDE source files.

2. Python 3.10+ and the Windows `py` launcher must be available. Stage 5 itself uses `py -3`.

## Run from PowerShell

Open PowerShell in the KBIDE root:

```powershell
cd "<KBIDE_ROOT>"
```

Convert all profiles:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\KidBright-Text-CLI-Demo-v0.1.0\tools\Convert-KBTExamplesToBlocklyXml.ps1" -Profile all -KbideRoot "."
```

Convert one profile only:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\KidBright-Text-CLI-Demo-v0.1.0\tools\Convert-KBTExamplesToBlocklyXml.ps1" -Profile core -KbideRoot "."
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\KidBright-Text-CLI-Demo-v0.1.0\tools\Convert-KBTExamplesToBlocklyXml.ps1" -Profile advanced -KbideRoot "."
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\KidBright-Text-CLI-Demo-v0.1.0\tools\Convert-KBTExamplesToBlocklyXml.ps1" -Profile plugins -KbideRoot "."
```

## Run by double-clicking a BAT file

- `KidBright-Text-CLI-Demo-v0.1.0\tools\Convert-CoreExamplesToXml.bat`
- `KidBright-Text-CLI-Demo-v0.1.0\tools\Convert-AdvancedExamplesToXml.bat`
- `KidBright-Text-CLI-Demo-v0.1.0\tools\Convert-PluginExamplesToXml.bat`
- `KidBright-Text-CLI-Demo-v0.1.0\tools\Convert-AllExamplesToXml.bat`

Or run the generic wrapper with a profile argument:

```cmd
KidBright-Text-CLI-Demo-v0.1.0\tools\Convert-KBTExamplesToBlocklyXml.bat all
```

## Output files

The generated XML is written under the KBIDE root:

```text
kbide\kbt-demo-output\blockly\
├── core\
├── advanced\
└── plugins\
```

The names match the original `.kbt` filenames, with `.xml` replacing `.kbt`.

## One-file command

The underlying Stage 5 compiler command is:

```powershell
py -3 .\app\kbt\compiler\kbtc.py blockly `
  .\app\kbt\examples\core\01_hello_world.kbt `
  --profile core `
  -o .\kbt-demo-output\hello_blocks.xml
```

You can also inspect the compiler stages:

```powershell
py -3 .\app\kbt\compiler\kbtc.py version
py -3 .\app\kbt\compiler\kbtc.py check .\app\kbt\examples\core\01_hello_world.kbt --profile core
py -3 .\app\kbt\compiler\kbtc.py ast .\app\kbt\examples\core\01_hello_world.kbt --profile core --json
```

## Important: Blockly XML, JavaScript generator API and C++

In this KidBright IDE version, the generator namespace is named `Blockly.JavaScript`, but the KidBright-specific generator functions produce **C++ source text**. The KBT adapter calls `Blockly.JavaScript.workspaceToCode(workspace)` and exposes it as `KBTBlockly.generateCppFromXml(xmlText)`.

Therefore, the implemented flow is:

```text
.kbt -> KBT compiler -> Blockly XML -> original KidBright Blockly generator functions -> C++
```

There is **not** a separate JavaScript-program output followed by a JavaScript-to-C++ transpiler in the Stage 5 implementation. There is also no `kbtc.py cpp` CLI command in Stage 5.0. The IDE's **Preview C++** button invokes the original browser-based generator bridge. These batch tools stop at Blockly XML.

For external plugin examples, Blockly XML translation can succeed even if a required plugin is not installed in another KBIDE installation. The corresponding plugin block definitions and generators must be available when C++ generation is performed.

## Sample output

The package `samples` folder contains the Hello World input (`hello_world.kbt`) and an actual Blockly XML file generated by the Stage 5 compiler (`hello_blocks.xml`). It is included as a reference for inspection and lecture slides.
